# 日志查看器 GUI 设计

## 1. 候选布局

### 方案 A：底部停靠面板（推荐）

延续现有 `QtLogPanel` 的 `QDockWidget`，面板内从上到下为统计概览、筛选栏、日志表格和详情
面板。Dock 可停靠底部/右侧、浮动或关闭。

优点：不改变现有主导航和页面上下文；日志是跨页面的辅助工具；停靠/浮动状态由 Qt 原生管理，
适合重复排障。缺点：窗口较窄时表格列需要折叠；详情区会压缩表格高度。

### 方案 B：独立日志窗口

主窗口只提供“打开日志”命令，日志查看器以独立 `QMainWindow` 展示。

优点：可最大化、同时对照存档操作；日志表格有更大空间。缺点：窗口生命周期和焦点管理复杂；
用户容易错过新日志；需要额外保存窗口几何状态。

### 方案 C：侧边栏标签页

在应用主侧边栏新增“日志”导航页，将统计、筛选和列表作为一个普通页面。

优点：布局稳定、适合长期查看和告警历史；与页面路由一致。缺点：日志属于全局辅助能力，切换页面
会丢失当前业务上下文；会扩大导航和翻译注册范围。

## 2. 推荐方案

采用方案 A。现有 `app/qtui/application.py` 已装配底部日志 Dock，迁移风险最小。推荐面板结构：

```text
┌─────────────────────────────────────────────────────────────┐
│ 今日总量 级别占比进度条 近7天趋势摘要                         │
├─────────────────────────────────────────────────────────────┤
│ 级别 | 起止时间 | 关键词 | 模块 | 筛选 | 实时                 │
├─────────────────────────────────────────────────────────────┤
│ QTableView：时间 | 级别 | 模块 | 消息 | 线程                  │
├─────────────────────────────────────────────────────────────┤
│ 详情：完整消息 / extra / 异常堆栈                             │
├─────────────────────────────────────────────────────────────┤
│ 清空当前视图 | 导出筛选结果 | 复制 | 状态/新日志提示           │
└─────────────────────────────────────────────────────────────┘
```

列表使用 `QAbstractTableModel`，JSONL 查询服务在后台流式扫描并只返回最近 300 条匹配记录。
UI handler 在存储 handler 之后接收记录；实时模式批量刷新并滚动到底部，非实时模式累计
“有 N 条新日志”。

## 3. 状态和交互

| 状态 | 反馈 |
|---|---|
| 空状态 | 面板状态区显示“暂无日志，应用启动后将自动记录” |
| 加载中 | 状态区显示不确定进度指示器，控件仍可关闭面板 |
| 无匹配 | 表格中央显示“无匹配日志”，保留筛选条件 |
| 新日志 | 实时模式追加并滚动；非实时模式显示可点击数量按钮 |
| 选中行 | 详情区显示完整消息、extra 和堆栈 |
| 复制成功 | 状态栏短暂显示“已复制” |
| 存储已满 | 状态栏显示轮转/清理结果；清理失败保留错误提示 |

所有耗时查询都由 `QThreadPool` worker 执行，使用 generation 丢弃迟到结果。列宽、筛选条件、
详情比例、Dock 状态和实时开关保存到 `QSettings`。
